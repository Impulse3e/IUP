# IUP — локальный прокторинг для аудитории

Сервер и панель преподавателя на одном компьютере, у участников — приложение **IUP Student** (камера, экран, микрофон). Работает в одной аудитории или по LAN, без облака.

Репозиторий: https://github.com/Impulse3e/IUP

```
IUP/
├── agent/          # IUP Student: лаунчер и прокторинг
├── server/         # FastAPI, SQLite, WebSocket
├── dashboard/      # панель (/) и кабинет участника (/student)
├── shared/         # типы и константы
├── scripts/        # установка, ярлыки, сборка, бэкап, брандмауэр
├── dist/           # IUP Student.exe после сборки (в git не входит)
└── docker-compose.yml
```

`.exe`, `.venv`, `.env`, `data/` и видео **в git не коммитятся**. После `git pull` сервер ставится скриптом, exe пересобирается на машине преподавателя.

---

## Что нужно

- Windows 10/11 (основной сценарий)
- Python **3.11+** с компонентом **Tcl/Tk** ([python.org](https://www.python.org/downloads/), галочки *Add to PATH* и *tcl/tk*)
- Камера, микрофон и разрешение на захват экрана у участника
- Для LAN: все ПК в одной сети, на сервере открыт порт **8000**

## Установка на компьютер преподавателя

В папке клона:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_windows.ps1
```

Скрипт создаёт `.venv`, ставит зависимости сервера, копирует `.env`, создаёт `data/`, заполняет демо-аккаунты и кладёт ярлык **IUP Teacher** на рабочий стол.

Запуск панели:

- ярлык **IUP Teacher**, или `scripts\run_teacher.bat`
- поднимает сервер на **http://127.0.0.1:8000** (слушает `0.0.0.0`, с других ПК в LAN тоже доступен)
- открывает браузер
- **окно консоли не закрывать**, пока идёт экзамен

Только сервер, без браузера: `scripts\run_server.bat`.  
Заново залить демо: `scripts\run_seed.bat`.

Вход в панель: `admin@iup.local` / `admin123`

### Собрать IUP Student.exe

Нужно после каждого обновления кода агента (вкладки, снимки, лаунчер):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_student_windows.ps1
```

Результат: `dist\IUP Student.exe` (~100–120 МБ). Ярлык **IUP Student** на рабочем столе обновится сам. Файл копируют на компьютеры участников — Python там не нужен.

Настройки и журнал агента: `%APPDATA%\iup\` (`launcher.json`, `agent.log`, эталон лица).

Готовые сборки CI, если есть: https://github.com/Impulse3e/IUP/releases

Альтернатива без exe (на той же машине, где есть `.venv`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_windows.ps1
scripts\run_student.bat
```

## Установка в аудитории (LAN)

1. На ПК преподавателя сервер уже запущен (**IUP Teacher**).
2. Один раз от администратора:

   ```
   scripts\allow_firewall_8000.bat
   ```

   Добавляет входящее правило TCP **8000** и печатает IPv4. Вручную:

   ```
   netsh advfirewall firewall add rule name="IUP Server 8000" dir=in action=allow protocol=TCP localport=8000
   ```

3. Узнать IPv4: `ipconfig` (например `192.168.1.10`).
4. Преподаватель и кабинет: `http://192.168.1.10:8000` и `http://192.168.1.10:8000/student`
5. В IUP Student: «Показать адрес сервера» → `http://192.168.1.10:8000`

Если страница не открывается: консоль сервера открыта, хост `0.0.0.0:8000`, устройства в одной Wi‑Fi/LAN, правило брандмауэра на **том** ПК, где сервер.

Копия базы: `scripts\backup_db.bat` → `data\backups\` (сервер также снимает снимок примерно раз в 6 часов).

## Как работать

### Преподаватель

1. **IUP Teacher** → войти (`admin@iup.local` / `admin123` или свой аккаунт).
2. **Экзамены** → название, по желанию описание, email первого студента, окно времени, слова для контроля вкладок → **Создать**.
3. **Управление**:
   - править начало/конец окна, закрыть экзамен вручную или открыть снова;
   - список слов в заголовках вкладок (сохраняется отдельно);
   - назначить участника по email (новому аккаунту пароль покажется **один раз**);
   - таблица исходов группы, выгрузка CSV/HTML.
4. Студенты входят в IUP Student или записываются в кабинете `/student`, если включена свободная запись.
5. **Live** — стена камер; красная рамка при критичном событии; клик по карточке — камера, лента, снимки.
6. **Проверка** — разобрать события, зачёт или аннулирование с комментарием, экспорт сессии CSV / JSON / HTML.
7. После экзамена можно закрыть окно консоли сервера.

Смена своего пароля: кнопка в сайдбаре панели. Пароль не короче 8 символов.

### Участник

1. Запустить **IUP Student** (exe или `run_student.bat`).
2. Войти тем же email, что в панели, или **Создать аккаунт**.
3. Выбрать экзамен → согласие на камеру/экран/микрофон → проверка устройств → эталон лица → окно камеры до конца попытки.
4. Если связь оборвалась, повторный вход в ту же сессию **не** требует заново согласие и лицо (файл в `%APPDATA%\iup\identity\`).
5. Кабинет без камеры: http://127.0.0.1:8000/student — запись на открытый экзамен, смена пароля, скачивание скрипта запуска.

Вне окна экзамена (ещё не начался / уже закрыт / закрыт вручную) войти и писать события нельзя.

## Функции текущей стадии

### Аккаунты

- Вход по email (регистр не важен) и паролю
- Регистрация участника: `/student` и кнопка в IUP Student; роль всегда `student`; сразу вход
- Смена пароля: кабинет, панель преподавателя, кнопка «Пароль» в приложении (нужен текущий)
- Преподаватель создаёт студента по email при создании экзамена или в «Назначить участнику»; пароль нового аккаунта показывается один раз
- Админ может завести пользователя любой роли (`POST /api/auth/register`)

### Экзамен

- Название, описание, свободная запись (`open_enrollment`)
- Окно `opens_at` / `closes_at` при создании и **после** (пустые даты — без ограничения)
- Ручное **закрытие** и **открытие снова** (даты окна не сбрасываются)
- Назначение попытки по email
- Список слов в заголовке активного окна (вкладки Chrome/Edge): предупреждение, не блокировка; не указывать `chrome`
- Таблица исходов группы: статус, риск, зачёт/аннулирование, комментарий, Live и Проверка
- Выгрузка исходов группы CSV и HTML

### IUP Student

- Вход, регистрация, смена пароля, адрес сервера
- Список своих сессий и доступных экзаменов
- Согласие, pre-check: камера, микрофон, захват экрана, число мониторов, запрещённые процессы
- Эталон лица (MediaPipe); сравнение в ходе экзамена
- Повторное подключение к сессии без повторного согласия и лица
- Heartbeat, повтор при обрыве сети

### Что снимает агент

- Вебкамера (окно «IUP Proctoring»), превью в Live
- Периодические кадры рабочего стола
- Микрофон (слишком тихо / слишком громко)
- Заголовок активного окна (контроль вкладок)
- Список процессов и число мониторов

### События прокторинга

| Событие | Смысл |
|---------|--------|
| Нет лица / несколько лиц | в кадре 0 или больше одного человека |
| Поворот головы | взгляд уведён от экрана |
| Тихий / громкий звук | пороги RMS |
| Другое лицо | не совпало с эталоном |
| Запрещённый процесс | Discord, Telegram, Zoom, Teams, Skype, OBS, AnyDesk, TeamViewer, RustDesk, виртуальные камеры |
| Потеря фокуса | переднее окно не браузер и не IUP |
| Второй монитор | больше одного экрана |
| Подозрительная вкладка | слово из списка экзамена в заголовке активного окна |
| Агент не отвечает / вмешательство | heartbeat или отладчик |

К критичным (чужое лицо, тампер, запрещённый процесс, несколько лиц, потеря heartbeat) — красная рамка на стене Live.

К вкладкам, запрещённым процессам, потере фокуса и второму монитору крепятся **кадр стола** и **кадр камеры**. Клипы в панели открываются как картинки (кадры из записи); сырой AVI браузер не играет.

Запрещены мессенджеры и удалённый доступ, **не** браузеры: экзамен обычно идёт в Chrome/Edge.

### Панель преподавателя

- Экзамены, управление, сессии
- Live: стена камер, выбор участника, лента событий, снимки
- Проверка: зачёт / аннулирование сессии, комментарий; по событию — подтвердить / ложное / аннулировать
- Экспорт одной сессии: CSV, JSON, HTML
- Смена пароля
- Админ: webhooks, ручной бэкап БД

### Кабинет `/student`

- Вход и регистрация
- Список назначенных и открытых экзаменов, запись
- Смена пароля
- Скачивание `.bat` / `.sh` запуска агента

### Сеть, данные, безопасность согласия

- JWT: `.env` `SECRET_KEY` или файл `data/secret.key` при старте
- SQLite `data/iup.db` (WAL)
- Файлы доказательств: `data/storage/`
- CORS для localhost и частных LAN-адресов
- WebSocket: токен в первом JSON `{type:"auth",token}`, не в URL
- Согласие участника до старта камеры и экрана
- Лимит загрузки файла (`MAX_UPLOAD_BYTES`, по умолчанию 20 МБ)
- Срок хранения `retention_days` / `RETENTION_DAYS`

## Linux / macOS

Fish: не вызывайте `source .venv/bin/activate`. Используйте `.venv/bin/python`.

```bash
chmod +x scripts/*.sh
./scripts/install.sh
cp -n .env.example .env
./scripts/run_server.sh
PYTHONPATH=. .venv/bin/python scripts/seed_demo.py
./scripts/run_student.sh
```

Ярлык Linux: `iup-student.desktop` (поправьте `Exec=`, если проект не в `~/IUP`).

Захват заголовка вкладки и PrintWindow окна рассчитаны на **Windows**.

## Важно перед коммитом и выкладкой

- Не коммитить `.env`, `.venv`, `data/`, `dist/`, `*.exe`, модели `models/*.task`
- После `git pull` на машине преподавателя: при необходимости `setup_windows.ps1`, затем **пересобрать exe**
- Смените демо-пароли, если это не учебный стенд
- LTI выключен, пока в `.env` нет `LTI_CLIENT_ID` и `LTI_LAUNCH_SECRET`
